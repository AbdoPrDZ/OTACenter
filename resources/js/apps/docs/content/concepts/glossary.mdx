# Glossary

**OTA (Over-The-Air)** — delivering an update to a device over a network instead of through an app store.

**Bundle** — a JS update uploaded to a version and downloaded by devices: for `react-ota-client`, an
archive with the JS bundle and a `manifest.json`; for Expo, a zip of `npx expo export`.

**Client type** — a version's `client_type`: `ota-client` (bare React Native, `react-ota-client`) or `expo`
(`expo-ota-client`).

**Demo release** — a version or bundle published only to testers: devices linked to users in a domain with
`allow_demo` that is bound to the app. See [Demo releases](/guides/demo-releases).

**Promote** — turn a demo release public, so every device receives it.

**Link code** — a one-time 8-character code that links a device to a user, making it eligible for demos.

**Expo Updates protocol** — the HTTP contract `expo-updates` uses to fetch a manifest and assets.
OTACenter implements it under `/ota-client/v1/expo/{package}`.

**Embedded bundle** — the JS bundle shipped inside the APK. The engine falls back to it when no
downloaded bundle has been activated.

**Active bundle** — the downloaded bundle a version currently points at, stored on
`versions.latest_id`.

**runtimeVersion** — a compatibility key in the bundle manifest that must match the host APK's
`versionName`. A JS-only update keeps the same `runtimeVersion`; native changes require a new APK.

**Session** — a token returned by `/ota-client/v1/app/info` for SDK compatibility; the OTA endpoints are authorized by
the `API-KEY` header, not this session.

**Device fingerprint** — the `X-Device-Info` header (`did`, `mf`, `br`, `mdl`, `av`, `sdv`) sent by the
client so the server can register and target devices.

**Domain** — an organizational grouping. Apps and users are bound to domains; a device receives an app
when one of its user's domains is bound to that app.

**Permission** — a named capability (`app.view`, `bundle.create`, …) held by a role or directly by a user.

**Role** — a named set of permissions; `super-admin` bypasses every permission check.

**Tab** — a dashboard page (`HomeTab`, `AppsTab`, …) mounted by the dashboard router.

**SPA** — one of the four single-page apps: `home`, `docs`, `auth`, `dashboard`.

**Tabling** — the server-side trait that powers every list endpoint (sort, search, filter, paginate).

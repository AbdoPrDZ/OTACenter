# Architecture overview

OTACenter is a **Laravel monolith with React SPAs** on the server side, plus a **separate React Native
client package**. It exposes two APIs: an admin API for the dashboard and a device API for the client SDK.

## The system at a glance

| Side | What it does |
|------|--------------|
| **Server** — Laravel | Admin API `/api/*` (Sanctum + permission middleware) · Device API `/ota-client/v1/*` (Sanctum ability + `DeviceMiddleware`) · models (`App`, `Version`, `Bundle`, `Domain`, `User`, `File`, `Device`) and the `Tabling` pipeline · files at `/files/{name}` |
| **SPAs** — Vite/React | `home` · `docs` · `auth` · `dashboard` |
| **Client** — `ota-client` | Kotlin engine + typed JS + CLI; talks over HTTPS with `X-Device-Info`, `API-KEY` and a session |

<Callout type="tip" title="Automatic rollback">
Install is two-phase: a bundle must confirm a successful launch, otherwise the next launch reverts to the
previous (or embedded) bundle. A bad OTA cannot brick the app.
</Callout>
